# Migration / Test-DB Setup Scripts (SQL Server)

Helper scripts used to build and populate the single consolidated app database
(`TestASSH`) from the legacy `ASSH` + `DB_ASSH` databases. Run in SSMS or via
`sqlcmd -S <server> -E -i <file>.sql`.

> The full ASSH schema script (`Create_TestASSH.sql`, ~4 MB, generated by SSMS
> "Generate Scripts") is **not** committed here — regenerate it from the live
> DB when needed. These scripts assume it has already created the empty
> `TestASSH` schema.

## Recommended order

1. **`Create_TestASSH.sql`** *(generated separately)* — creates the empty
   `TestASSH` database with the ASSH schema (all filegroups redirected to PRIMARY).
2. **`Copy_DutyRoster_to_TestASSH.sql`** — copies the ~43 duty-roster tables'
   data from `ASSH` (roster, shifts, employees, workflow, masters).
   *(or `Copy_ASSH_to_TestASSH.sql` for the full ERP data — heavy.)*
3. **`Copy_Atten_to_TestASSH.sql`** — copies the monthly attendance tables
   (`Atten_MMYYYY`, the daily punches) that have data. **Required for
   View Attendance to show punches.**
4. **`Replace_DR_Tables_from_DB_ASSH.sql`** — replaces the stale `ASSH` copies of
   `DR_CorrectionRequest`, `DR_ChangeSchedule`, `DR_OverTime`, `DR_Audit`,
   `EmployeeWorkingHours`, `DR_EmployeeDutyRoster` with the authoritative
   `DB_ASSH` versions (consolidates to one database).
   - `Consolidate_DB_ASSH_into_TestASSH.sql` / `Fill_DR_Tables_from_DB_ASSH.sql`
     are earlier/narrower variants of the same idea; `Replace_*` supersedes them.
5. **`../app_users.sqlserver.sql`** — creates the app login table
   (`dr_app_users`) + the default `admin` account. The one table the legacy
   schema doesn't provide.
6. **`Restore_Identity_AutoNumbering.sql`** — **required after the copies.**
   `SELECT ... INTO` drops the IDENTITY property, so NOT NULL key columns the
   app doesn't populate (`DR_CorrectionRequest.SNo` / `RequestID`,
   `Schedule_Request.ID`, `AllotShift`/`AllotShiftDetail.ID`, …) reject inserts
   with *"Cannot insert the value NULL into column …"*. This restores
   auto-numbering in place (a SEQUENCE + DEFAULT per column) without rebuilding
   the tables, and prints a diagnostic of any column that could still block.

## Notes
- All copy scripts are idempotent-ish and skip tables already present / empty.
- `SELECT ... INTO` copies structure + data, **but NOT the IDENTITY property**,
  PKs, indexes, or constraints. The dropped identity is why inserts fail with a
  NULL-key error until `Restore_Identity_AutoNumbering.sql` is run.
- These operate on real hospital data; treat `TestASSH` with production-grade
  access controls.
